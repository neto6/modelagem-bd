Aula 2.5

O que você vai sair sabendo

  • Ordenar resultados com ORDER BY
  • Limitar com TOP
  • Agrupar com GROUP BY e filtrar grupos com HAVING
  • Usar funções de agregação: SUM, COUNT, AVG, MIN, MAX
  • Remover duplicatas com DISTINCT
Ordenando

ORDER BY

Decidir a ordem em que os resultados aparecem.

-- Crescente (padrão)
SELECT nome, nivel FROM personagens
ORDER BY nivel;

-- Decrescente
SELECT nome, nivel FROM personagens
ORDER BY nivel DESC;

-- Por múltiplas colunas
SELECT nome, classe_id, nivel FROM personagens
ORDER BY classe_id ASC, nivel DESC;
Dica Sem ORDER BY, o SQL Server não garante ordem. Não confie em "a ordem em que inseri".
Limitando

TOP

Só quero os primeiros N resultados.

-- Top 10 personagens mais fortes
SELECT TOP 10 nome, nivel
FROM personagens
ORDER BY nivel DESC;

-- Top 5% mais ricos (em ouro)
SELECT TOP 5 PERCENT nome, ouro
FROM personagens
ORDER BY ouro DESC;
Combine sempre com ORDER BY TOP sem ORDER BY pega "qualquer 10", e isso pode mudar a cada execução.

SUM, COUNT, AVG, MIN, MAX

Calculando

Calculando sobre toda a tabela

-- Quantos personagens existem
SELECT COUNT(*) AS total_personagens
FROM personagens;

-- Nível médio
SELECT AVG(nivel) AS nivel_medio
FROM personagens;

-- Valor total dos items mais caros (raros e épicos)
SELECT SUM(valor) AS valor_total
FROM items
WHERE raridade IN ('Raro', 'Épico');

-- Várias agregações de uma vez
SELECT
  COUNT(*) AS total,
  MIN(nivel) AS menor_nivel,
  MAX(nivel) AS maior_nivel,
  AVG(nivel) AS nivel_medio
FROM personagens;
Agrupando

GROUP BY

Em vez de calcular sobre tudo, calcular por categoria.

-- Quantos personagens por classe
SELECT classe_id, COUNT(*) AS total
FROM personagens
GROUP BY classe_id;

-- Nível médio por classe
SELECT classe_id, AVG(nivel) AS nivel_medio
FROM personagens
GROUP BY classe_id;

-- Quantos items por raridade
SELECT raridade, COUNT(*) AS quantidade, SUM(valor) AS valor_total
FROM items
GROUP BY raridade;
Regra de ouro Toda coluna no SELECT precisa estar no GROUP BY ou dentro de uma função de agregação. Senão, erro.
Filtrando grupos

HAVING

WHERE filtra linhas. HAVING filtra grupos.

-- Classes com mais de 50 personagens
SELECT classe_id, COUNT(*) AS total
FROM personagens
GROUP BY classe_id
HAVING COUNT(*) > 50;

-- Raridades com valor total acima de 10.000
SELECT raridade, SUM(valor) AS total
FROM items
GROUP BY raridade
HAVING SUM(valor) > 10000;
Pra lembrar WHERE vem antes do GROUP BY (filtra os dados que vão entrar). HAVING vem depois (filtra os grupos resultantes).
Removendo duplicatas

DISTINCT

Quero a lista de valores únicos, sem repetir.

-- Quais tipos de item existem
SELECT DISTINCT tipo FROM items;

-- Quais classes têm personagens (sem repetir classe_id)
SELECT DISTINCT classe_id FROM personagens;

-- Combinação única de classe e raridade
SELECT DISTINCT classe_id, raridade
FROM personagens_items;
Aplicando no RPG

Top jogadores

Casos clássicos de leaderboard.

-- Top 10 personagens mais fortes
SELECT TOP 10 nome, nivel, experiencia
FROM personagens
ORDER BY nivel DESC, experiencia DESC;

-- Top 3 personagens de cada classe
-- (versão simplificada por enquanto, vamos refinar em aulas futuras)
SELECT TOP 3 nome, classe_id, nivel
FROM personagens
WHERE classe_id = 1
ORDER BY nivel DESC;
Aplicando no RPG

Quem é a classe dominante?

-- Quantos personagens por classe + nível médio
SELECT
  classe_id,
  COUNT(*) AS total_personagens,
  AVG(nivel) AS nivel_medio,
  MAX(nivel) AS nivel_maximo
FROM personagens
GROUP BY classe_id
ORDER BY total_personagens DESC;

-- Classes com pelo menos 100 personagens nível 50+
SELECT classe_id, COUNT(*) AS total
FROM personagens
WHERE nivel >= 50
GROUP BY classe_id
HAVING COUNT(*) >= 100;
Aplicando no RPG

Quanto vale o tesouro?

-- Total de items por raridade
SELECT
  raridade,
  COUNT(*) AS quantidade,
  SUM(valor) AS valor_total,
  AVG(valor) AS valor_medio,
  MAX(valor) AS valor_maior
FROM items
GROUP BY raridade
ORDER BY valor_total DESC;

-- Tipos de item que valem mais de 1000 em média
SELECT tipo, AVG(valor) AS valor_medio
FROM items
GROUP BY tipo
HAVING AVG(valor) > 1000
ORDER BY valor_medio DESC;
Boas práticas

Antes de seguir em frente

  1. Aliases ajudamCOUNT(*) AS total em vez de uma coluna sem nome. Resultado fica legível.
  2. ORDER BY no finalÉ a última cláusula. Depois de WHERE, GROUP BY e HAVING.
  3. WHERE antes de GROUP BYFiltra dados antes de agrupar. Mais rápido.
  4. HAVING pra agregaçõesFiltrar resultado de SUM/COUNT/AVG não cabe no WHERE.
  5. DISTINCT é caroSe você acha que precisa, talvez seu modelo permita duplicatas que não deveria.

Tire 5 relatórios do RPG

~25 minutos. Escreva as 5 queries abaixo.

  1. Os 5 personagens com maior experiência, mostrando nome, classe e nível
  2. Para cada classe: quantos personagens existem e o nível médio
  3. Quantidade total de items por raridade, ordenado do mais raro pro mais comum
  4. Classes com mais de 100 personagens ativos
  5. Magia mais cara (maior custo_mana) e a mais barata, com nome e custo
Atenção Pelo menos 3 dessas queries vão precisar de GROUP BY. Se você não usou em nenhuma, releia o enunciado.
