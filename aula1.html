⚡

Sem modelar

Primeira semana voa. Tabelas saem rápido.

Aos poucos: dados duplicados, relacionamento errado, refatoração dolorida.

🎯

Modelando

Primeiro dia parece perda de tempo.

Mas o banco nasce coerente. Mudanças futuras são localizadas, não cirurgias.

Regra Modelar custa horas. Não modelar custa meses.

Conceito

Entidades

Coisas do mundo real que têm existência própria e merecem ser registradas.

Como identificar

  • Substantivos do domínio
  • Você consegue contar quantos existem
  • Tem atributos próprios
  • Faz sentido falar dela isoladamente

No nosso joguinho RPG

  • Conta: quem joga
  • Personagem: quem é jogado
  • Item: o que se carrega
  • Magia: o que se lança
  • Classe: tipo de personagem
Conceito

Atributos

As características que descrevem cada entidade.

Tipos

  • Simples: nome, nível, dano
  • Compostos: endereço (rua, cidade, CEP)
  • Multivalorados: telefones, tags
  • Derivados: idade (vem da data_nasc)
  • Identificador: chave candidata

Personagem

Personagem {
  id            // identificador
  nome
  classe
  nivel
  vida_max
  mana_max
  experiencia
  data_criacao
}
Conceito

Relacionamentos

Como as entidades se conectam. Geralmente é um verbo do domínio.

Conta POSSUI Personagem

Uma conta pode ter vários personagens. Cada personagem pertence a uma conta.

Personagem CARREGA Item

Um personagem carrega muitos itens. O mesmo tipo de item pode estar com vários personagens.

Personagem CONHECE Magia

Um personagem aprende várias magias. Cada magia pode ser conhecida por muitos personagens.

Personagem É DA Classe

Cada personagem tem uma classe. Uma classe pode ter vários personagens.

Conceito

Cardinalidade

Quantos de um se relacionam com quantos de outro?

1 : 1

Personagem ↔ Ficha Detalhada

Cada personagem tem exatamente uma ficha. Raro na prática.

1 : N

Conta → Personagens

Uma conta tem N personagens. O mais comum.

N : N

Personagem ↔ Item

Muitos para muitos. Sempre vira tabela associativa no lógico.

Pergunta-chave "Um X pode ter quantos Y?" E depois inverte: "Um Y pode estar com quantos X?"

Boas práticas

Antes de fechar o DER

  1. Comece pelo domínio, não pelas tabelasListe o que existe no mundo real. Tabela é detalhe técnico que vem depois.
  2. Use nomes do negócio"Personagem" e não "tbl_char". O DER é pra todos lerem, não só devs.
  3. Valide com quem entendeMostre pra um stakeholder e pergunte se a história bate.
  4. Espere iterarPrimeiro DER nunca é o final. Está ok.

Desafio em aula

Adicione Guildas ao RPG

~20 minutos. Pode fazer em dupla.

  • Modele a entidade Guilda com seus atributos (nome, descrição, data de fundação, líder...)
  • Defina o relacionamento entre Personagem e Guilda
  • Um personagem pode estar em quantas guildas? Uma guilda tem quantos personagens?
  • E o líder da guilda? Como representar?
  • Desenhe no Diagrama de Entidade-Relacionamento
Dica Não tem resposta única. O importante é a cardinalidade refletir uma regra de negócio que você consiga justificar.
