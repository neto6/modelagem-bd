Aula 4

O que você vai sair sabendo

  • Por que JOIN é necessário
  • Usar INNER JOIN quando só quer o que combina
  • Usar LEFT/RIGHT JOIN quando quer manter um lado
  • Usar FULL JOIN quando quer tudo dos dois lados
  • Encadear múltiplos JOINs
Conceito

O problema sem JOIN

Modelo normalizado guarda dados em tabelas separadas. Mas quase sempre você precisa de tudo junto.

Sem JOIN

SELECT em personagens te dá conta_id e classe_id, que são números. Você não consegue ver o nome do dono ou da classe.

Com JOIN

Combina linhas de personagens com linhas de contas e classes. Resultado tem nome do personagem, login do dono e nome da classe na mesma linha.

Regra Cada FK no modelo é um JOIN potencial nas suas queries.
Tipos de JOIN

INNER JOIN

Só traz linhas que combinam nos dois lados.

-- Personagens com nome da classe (só os que têm classe válida)
SELECT
  p.nome AS personagem,
  c.nome AS classe,
  p.nivel
FROM personagens p
INNER JOIN classes c ON p.classe_id = c.id;
Comportamento Se o personagem tem classe_id NULL ou apontando pra classe que não existe, ele não aparece. INNER JOIN é restritivo.
Tipos de JOIN

LEFT JOIN

Traz tudo do lado esquerdo. Do direito, só o que combina (NULL se não tiver).

-- Todos os personagens, com guilda se tiver
SELECT
  p.nome AS personagem,
  g.nome AS guilda
FROM personagens p
LEFT JOIN guildas g ON p.guilda_id = g.id;
Caso clássico "Liste X e o Y associado, mesmo que não tenha Y." Resultado: linhas onde guilda é NULL pra personagens sem guilda.
Tipos de JOIN

RIGHT JOIN

O contrário do LEFT. Tudo do lado direito.

-- Todas as classes, com personagens (mesmo classes sem nenhum)
SELECT
  c.nome AS classe,
  p.nome AS personagem
FROM personagens p
RIGHT JOIN classes c ON p.classe_id = c.id;
Na prática RIGHT JOIN é raro. Em vez de RIGHT, inverta a ordem e use LEFT. Fica mais natural de ler.
Tipos de JOIN

FULL JOIN

Tudo dos dois lados. Onde não combina, vira NULL.

-- Comparar duas listas: personagens e classes
-- Mostra personagens sem classe, classes sem personagens, e o que combina
SELECT
  p.nome AS personagem,
  c.nome AS classe
FROM personagens p
FULL JOIN classes c ON p.classe_id = c.id;
Quando usar Auditoria, comparar duas fontes pra ver o que está faltando em cada lado. Não é o JOIN do dia a dia.
Encadeando

Vários JOINs em sequência

Cada JOIN adiciona mais informação ao resultado.

-- Personagem, conta, classe e guilda (tudo de uma vez)
SELECT
  p.nome AS personagem,
  c.login AS dono,
  cl.nome AS classe,
  g.nome AS guilda
FROM personagens p
INNER JOIN contas c ON p.conta_id = c.id
INNER JOIN classes cl ON p.classe_id = cl.id
LEFT JOIN guildas g ON p.guilda_id = g.id
WHERE p.nivel >= 50
ORDER BY p.nivel DESC;
Misture INNER e LEFT INNER pra obrigatórios, LEFT pros opcionais. No exemplo: conta e classe são obrigatórias, guilda é opcional.
Boas práticas

Apelidos pras tabelas

Sem alias, queries com JOIN ficam ilegíveis.

-- Sem alias (verboso)
SELECT personagens.nome, classes.nome
FROM personagens
INNER JOIN classes ON personagens.classe_id = classes.id;

-- Com alias (legível)
SELECT p.nome, c.nome
FROM personagens p
INNER JOIN classes c ON p.classe_id = c.id;
Padrão Use letras curtas e mnemônicas. p pra personagens, c pra classes, i pra items. Quando tabelas começam com a mesma letra, escolha 2-3 caracteres (pe e pa, por exemplo).
Aplicando no RPG

Mostrando inventário com nome dos items

-- O inventário guarda só os IDs. Pra ver os nomes, JOIN com items.
SELECT
  p.nome AS personagem,
  i.nome AS item,
  i.raridade,
  inv.quantidade,
  i.valor * inv.quantidade AS valor_total
FROM inventario inv
INNER JOIN personagens p ON inv.personagem_id = p.id
INNER JOIN items i ON inv.item_id = i.id
WHERE p.id = 1
ORDER BY i.valor DESC;
Padrão importante Tabela associativa quase sempre vem com 2+ JOINs (um pra cada lado da relação).
Aplicando no RPG

Procurando o que falta com LEFT JOIN

-- Personagens que NÃO têm nenhum item no inventário
SELECT
  p.nome AS personagem,
  p.nivel
FROM personagens p
LEFT JOIN inventario inv ON p.id = inv.personagem_id
WHERE inv.personagem_id IS NULL;

-- Classes que ninguém escolheu (sem personagens)
SELECT
  c.nome AS classe
FROM classes c
LEFT JOIN personagens p ON c.id = p.classe_id
WHERE p.id IS NULL;
Truque comum LEFT JOIN + WHERE IS NULL = "me mostre o que NÃO tem correspondência no outro lado".
Boas práticas

Antes de seguir em frente

  1. Sempre use aliasQueries com JOIN sem alias viram um inferno de manter.
  2. INNER por padrãoUse LEFT só quando precisar manter um lado vazio. INNER é mais rápido.
  3. ON é a condição do JOIN, WHERE é filtroNão misture. ON liga as tabelas, WHERE filtra o resultado.
  4. Cuidado com produto cartesianoEsqueceu o ON? Linha de A x linha de B. Em tabelas grandes, isso explode.
  5. Pense no índiceJOINs em colunas sem índice ficam lentos. PK e FK geralmente têm índice automático, mas verifique.
