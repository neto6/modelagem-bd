Fundamentos

A família SQL

SQL não é uma coisa só. Tem três famílias principais.

DDL

Data Definition Language

Define estrutura. CREATE, ALTER, DROP, TRUNCATE.

Foco de hoje

DML

Data Manipulation Language

Mexe nos dados. INSERT, UPDATE, DELETE, SELECT.

Aula 2

DCL

Data Control Language

Controla acesso. GRANT, REVOKE, DENY.

Fora do escopo

Primeiro comando

CREATE DATABASE

O ponto de partida. Sem banco, não tem tabela.

-- Forma mais simples
CREATE DATABASE rpg_game;

-- A partir daqui, todos os comandos rodam nesse banco
USE rpg_game;

-- Pra apagar (cuidado)
DROP DATABASE rpg_game;
Por baixo dos panos O SQL Server cria dois arquivos: .mdf (dados) e .ldf (log de transações). Por enquanto não se preocupe com isso.
Anatomia

CREATE TABLE

A estrutura básica que vamos repetir várias vezes hoje.

CREATE TABLE contas (
  id            INT            IDENTITY(1,1) NOT NULL,
  login         NVARCHAR(50)   NOT NULL,
  email         NVARCHAR(120)  NOT NULL,
  senha_hash    NVARCHAR(255)  NOT NULL,
  data_criacao  DATETIME       NOT NULL
);

Coluna

Nome curto, descritivo, snake_case. Evite abreviações criativas.

Tipo

O contrato com o SGBD sobre o que aquela coluna vai guardar.

Modificadores

NULL/NOT NULL, IDENTITY, DEFAULT, e (em breve) constraints.

Tipos de dados

Não precisa decorar todos. Os mais usados resolvem 95% dos casos.

Decisões importantes

Escolhendo o tipo certo

Erro aqui é caro depois. Pense duas vezes antes de fechar o tipo.

VARCHAR vs NVARCHAR

VARCHAR = ASCII. NVARCHAR = Unicode (acentos, emoji, kanji).

Vamos usar NVARCHAR nos nossos exemplos por garantia.

NVARCHAR(N) vs NVARCHAR(MAX)

Se você sabe que o texto tem limite (login até 50, email até 120), defina o tamanho.

MAX só pra conteúdo de tamanho realmente imprevisível.

DATETIME e DATE

DATETIME pra data e hora juntos.

Se só importa o dia, use DATE.

DECIMAL pra dinheiro

Nunca FLOAT pra valores monetários. Arredondamento binário causa centavos perdidos.

Use DECIMAL(10,2) ou similar.

Modificadores

NULL vs NOT NULL

Quando o valor é opcional, e quando ele é obrigatório.

NULL = opcional

  • Ausência de valor
  • Não é zero, não é string vazia
  • Qualquer comparação com NULL retorna desconhecido
  • Padrão se você não disser nada

NOT NULL = obrigatório

  • Tentar inserir sem valor dá erro
  • Use sempre que a coluna não faz sentido vazia
  • Login, email, data de criação devem ser NOT NULL
Regra de ouro Default deveria ser NOT NULL. Só permita NULL quando faz sentido de negócio (ex: data_ultimo_login a princípio vai ser NULL).
Modificadores

IDENTITY

Auto incremento. O jeito mais comum de gerar chaves primárias.

-- IDENTITY(seed, incremento)
id INT IDENTITY(1,1) NOT NULL

-- Você não insere o id, o SQL Server gera
INSERT INTO contas (login, email, senha_hash, data_criacao)
VALUES ('arthas', 'arthas@rpg.com', '...', GETDATE());

-- Pegar o id que acabou de ser gerado
SELECT SCOPE_IDENTITY();
Dica IDENTITY(1,1) começa em 1 e incrementa de 1. É o que você quer 99% das vezes.

CREATE TABLE personagens (

Quando precisar mudar

ALTER e DROP

Modelos evoluem. Saber alterar é tão importante quanto saber criar.

-- Adicionar coluna
ALTER TABLE personagens
ADD guilda_id INT NULL;

-- Remover coluna
ALTER TABLE personagens
DROP COLUMN guilda_id;

-- Alterar tipo (cuidado, pode dar erro se tiver dado incompatível)
ALTER TABLE personagens
ALTER COLUMN nome NVARCHAR(100) NOT NULL;

-- Remover tabela inteira (sem volta)
DROP TABLE personagens;
Atenção DROP TABLE apaga estrutura e dados. Não tem CTRL+Z. Em produção, sempre script revisado e backup antes.
Boas práticas

Antes de seguir em frente

  1. Nomenclatura consistenteEscolha plural ou singular pra tabelas (contas vs conta) e mantenha. snake_case nas colunas.
  2. NOT NULL por padrãoNULL é exceção, não regra. Pergunte sempre: faz sentido essa coluna ficar vazia?
  3. IDENTITY pra PK numéricaSimples, eficiente, evita conflitos. Use até ter motivo forte pra outra coisa.
  4. Tipo do tamanho certoNVARCHAR(50) pra login, não NVARCHAR(MAX). SMALLINT pra nível, não BIGINT. Economiza espaço e processamento.
